# Витрина бронирований в DuckDB

Одна строка `fact_booking` = одно бронирование, представленное отдельной записью
фиксированного исходного CSV. Модель описана в [passport.md](passport.md)
и [star.md](star.md): один факт и пять измерений.

## Запуск

Нужны Python 3.11+ и два исходника: `data/raw/H1.csv`, `data/raw/H2.csv`.
Из корня проекта:

```powershell
python -m pip install -r requirements.txt
python scripts/load_duckdb.py
```

Результаты:

- `data/booking.duckdb` — локальная база с шестью таблицами;
- `data/checks_duckdb.txt` — последний отчёт, записанный Python-скриптом;
- `data/checks_duckdb_repeat.txt` — сохранённый результат сверки двух запусков;
- `sql/ddl_duckdb.sql` — создание таблиц с первичными и внешними ключами;
- `sql/check_duckdb.sql` — проверочные запросы; выполняются загрузчиком,
  поскольку сверка с сырьём использует временную таблицу `raw_booking`.

## Загрузка и повторный запуск

`scripts/load_duckdb.py` читает CSV стандартным модулем Python `csv`, обрезает
пробелы, распознаёт пустые строки и маркеры `NULL`, `NA`, `N/A` как пропуски
(в текущем сырье `NA` встречается в `Children`). Номер записи
данных начинается с 1 без заголовка. `booking_id` имеет вид `H1:1`, `H2:1`.
Совпадающие по содержимому записи не удаляются. Сырьё не изменяется.

Даты заезда собираются из года, названия месяца и дня.
Пропуски измерений ссылаются на явные значения `UNKNOWN`; неизвестная дата имеет
ключ 0. Календарь непрерывный от минимальной до максимальной даты заезда/статуса,
`day_of_week` — от 1 (понедельник) до 7 (воскресенье).
Пропуски числовых мер сохраняются как SQL NULL. `adr` хранится как `DECIMAL(18,2)`.

При каждом запуске шесть таблиц витрины пересоздаются и загружаются целиком
в одной транзакции. Повторная загрузка не удваивает бронирования. Ручные изменения
этих таблиц, включая учебные версии отелей, при пересоздании заменяются исходными
данными. При ошибке загрузки или несовпадении проверок транзакция откатывается;
скрипт завершается с ненулевым кодом. Отчёт сверки с FAIL сохраняется, если
загрузка дошла до выполнения проверок.

## Проверки

Загрузчик выполняет SQL и выводит/сохраняет фактическое и ожидаемое значение
каждой проверки: число фактов в целом и по файлам, размеры справочников с учётом
неизвестных значений, пустые ключи, отсутствующие ссылки, соответствие типов
номеров отелю, интервалы версий, дубли booking_id, сохранение пропусков детей.
