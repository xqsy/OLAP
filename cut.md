# Границы проекта

Домен D5 — бронирования двух отелей H1/H2. Главная метрика — количество бронирований со статусом Check-Out, период анализа — по дате заезда.

| Что не делаем | Почему | Последствие для отчётов |
|--------------|--------|------------------------|
| Подтверждённая выручка, прибыль, оплаты и возвраты | Нет платёжного журнала, расходов и комиссий каналов | ADR не доказывает получение оплаты; нельзя определить прибыльность канала. |
| Загрузка номерного фонда и RevPAR | Нет количества доступных номеров по дням | Количество бронирований не является процентом загрузки отеля. |
| История бронирования и снимки портфеля на прошлую дату | Есть итоговый статус, но нет полного журнала изменений | Нельзя восстановить, сколько активных бронирований было известно отелю на произвольную дату. |
| Уникальные гости, повторные визиты одного человека и LTV | Нет устойчивого идентификатора гостя | Повторные бронирования нельзя надёжно связать с конкретным человеком. |
| Распределение ночей по календарным дням проживания | Зерно факта — бронирование, период — по дате заезда | Все ночи бронирования относятся к месяцу заезда; это не количество ночей, фактически проведённых именно в этом месяце. |
| Расшифровка и ранжирование типов номеров | Типы анонимизированы и представлены кодами | Нельзя объявить смену кода повышением или понижением категории; коды рассматриваем внутри отеля. |
| Потоковая загрузка через Kafka | Планируем пакетную загрузку CSV | Обновления появятся после очередной загрузки, без оперативности в реальном времени. |
| Кластер ClickHouse | Используем один учебный экземпляр | Не проверяем отказоустойчивость и масштабирование на нескольких узлах. |

## Границы истории

**З06, вариант B — отказ от SCD2.** Не храним историю атрибутов dim_hotel, dim_country, dim_channel и dim_room_type; принимаем SCD1 с актуальными значениями для всей истории бронирований. Текущие бизнес-вопросы не требуют классификации справочников «как было на дату события», а исходные CSV не содержат журнала её изменений.

- dim_date: календарные признаки фиксированы; ошибки вычисления исправляем.
- dim_hotel: одна строка на hotel_id, без версий. При перезаписи hotel_type старые бронирования в отчёте по типам отеля перейдут в новый тип. Историческое распределение по типам может измениться; восстановить прежний тип на дату заезда нельзя. Три текущих бизнес-вопроса используют код отеля, канал/сегмент и код страны, поэтому изменение только hotel_type не меняет их результаты.
- dim_country: код страны и значение «неизвестно». Исправление ошибочного кода меняет распределение прошлых бронирований по странам. Названий и регионов сейчас нет; если их добавим и будем перезаписывать по SCD1, прежние названия и региональную классификацию также не восстановим.
- dim_channel: уникальная пара сегмента и канала. Новое реальное сочетание получает отдельный ключ и не меняет старые бронирования. Исправление или объединение существующих значений меняет распределение прошлых бронирований по сегментам/каналам; отчёт в прежней классификации воспроизвести нельзя.
- dim_room_type: уникальная пара отеля и кода типа. Новый реальный код добавляем отдельно. Исправление кода или объединение ошибочных дублей меняет группировку прошлых бронирований по типам номеров. Описаний категорий сейчас нет; история будущих описаний также вне проекта.

Эту цену принимаем: анализируем бронирования с актуальными значениями справочников, не обещаем историческую классификацию на дату события. Если она понадобится, потребуются источник датированных изменений и пересмотр решения об истории. Редкость изменения атрибута сама по себе не является основанием отказа.

Загрузчик полностью пересоздаёт витрину из фиксированных H1/H2; отдельный механизм инкрементальных обновлений SCD1 не реализуем. Ручные исправления в базе при перезагрузке теряются: воспроизводимые исправления должны быть отражены в правилах преобразования или входных данных, при этом исходные CSV проекта сохраняем. Тип отеля определяем по файлу для всего периода; достоверную историю его изменений не восстанавливаем. История статусов самого бронирования также остаётся вне проекта.
