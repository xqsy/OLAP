# З03. Таблицы в DuckDB

**Практика:** [[P03_витрина_duckdb|P03]]  
**Вход:** [[З02_паспорт_star|паспорт]] и файлы из [[З01_стенд_и_сырьё|З01]]

---

## Зачем

Превратить паспорт в **реальные таблицы** и залить в них сырьё.  
DuckDB — локальная аналитическая база на файлах. Это песочница. Сервер ClickHouse появится на [[З07_загрузка_clickhouse|З07]] и на зачёте обязателен.

## Что сделать

1. Написать SQL создания справочников и таблицы событий.
2. Загрузить данные из `data/raw/`.
3. Проверить число строк и сумму главной меры.

---

## Ход работы

### 1. Создайте таблицы

Файл `sql/ddl_duckdb.sql` — SQL, который описывает таблицы, ещё без анализа.

По паспорту:

- справочники — `dim_store`, `dim_product` и так далее;
- события — `fact_sales` (или ваше имя);
- поля и ключи — как договорились, без десятка колонок «на всякий случай».

> [!tip]
> Деньги — тип `DECIMAL`, не `FLOAT`. Иначе на [[З11_сверка_sql_bi|З11]] SQL и карточка дашборда разъедутся на копейки.

### 2. Загрузка

Перенесите CSV/Parquet из `data/raw/` в таблицы (`COPY`, `read_csv` или небольшой скрипт).  
Способ должен повторяться из README, а не только «нажал в DBeaver».

### 3. Проверки

Сохраните вывод:

| Что смотрим | Зачем |
|-------------|--------|
| сколько строк в факте и справочниках | сходится ли с файлами |
| пустые ключи | битые строки |
| `sum` главной меры | первое зафиксированное число метрики |

### 4. Если грузите второй раз

Либо очистили таблицы и залили заново, либо в README одна фраза: как не получить удвоенные продажи.

- [ ] Повторная загрузка не раздувает факт (или это описано)
