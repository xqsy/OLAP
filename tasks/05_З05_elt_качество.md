# З05. Загрузка и проверки

**Практика:** [[P05_elt_качество|P05]]  
**Вход:** таблицы и эталон метрики из [[З03_витрина_duckdb|З03]]–[[З04_аналитический_sql|З04]]

---

## Зачем

Сделать заливку данных **повторяемым скриптом**, а не ручным «ещё раз вставил в DBeaver».

На курсе такой скрипт часто называют ELT: взяли сырьё → положили и проверили → получили чистые таблицы витрины.

## Что сделать

1. Собрать цепочку: исходные файлы → (по желанию промежуточные таблицы) → справочники → факт.
2. Встроить простые проверки качества.
3. Доказать: второй запуск **не удваивает** продажи или события.

---

## Ход работы

### 1. Папка `etl/`

Скрипт на Python или набор SQL — как удобно.  
Порядок важен: **сначала справочники, потом факт**. Иначе в факте появятся ссылки на магазины, которых ещё нет.

### 2. Проверки (минимум)

Перед тем как считать загрузку успешной, проверьте:

| Проверка | Что это значит |
|----------|----------------|
| пустые суммы и ключи | обязательные поля не null |
| странный диапазон | количество ≥ 0, даты не из 1900 года |
| дубли | нет двух строк с одним и тем же смыслом «одна строка = …» |
| «сироты» | в факте есть `store_id`, которого нет в справочнике магазинов |

Если проверка не прошла — **останавливайте** загрузку. Не оставляйте это на фильтр дашборда.

### 3. Два прогона подряд

Запустите загрузку дважды. Сравните число строк и сумму главной метрики.  
Если выросло вдвое — нет стратегии повтора. Обычно: очистили таблицы за период и залили заново (повтор не должен портить результат).

В README к etl одна фраза: что именно чистим при повторе.

## Что сдать

- скрипт в `etl/`
- лог двух прогонов (counts и sum метрики)

## Проверка

- [ ] Плохие данные останавливают загрузку
- [ ] Справочники раньше факта
- [ ] Второй прогон не раздувает факт
