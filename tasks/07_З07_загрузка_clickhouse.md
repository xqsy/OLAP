# З07. Данные в ClickHouse

**Практика:** [[P07_загрузка_clickhouse|P07]]  
**Вход:** витрина DuckDB из [[З03_витрина_duckdb|З03]], эталонный SQL из [[З04_аналитический_sql|З04]]

---

## Зачем

Перенести витрину в **ClickHouse** — серверную аналитическую базу, которая на зачёте обязательна. DuckDB остаётся лабораторией. Для дашборда источник — ClickHouse.

## Что сделать

1. Описать таблицы в ClickHouse (движок **MergeTree** — обычный для курса способ хранить данные кусками на диске).
2. Загрузить туда те же справочники и таблицу событий, что уже есть в DuckDB.
3. Сверить числа с DuckDB и убедиться, что повторная загрузка не плодит дубли.

---

## Ход работы

### 1. DDL под ClickHouse

Файл `sql/ddl_clickhouse.sql`.

Таблицы делайте на **MergeTree** (или семействе вроде `ReplacingMergeTree`, если понимаете зачем).  
Не копируйте схему «как в Postgres»: в ClickHouse нет обычного первичного ключа, который запрещает повтор строк.

Вместо этого задаёте **`ORDER BY`** — порядок, в котором строки лежат на диске.  
Если чаще фильтруете по дате и магазину, положите их в начало `ORDER BY`. Тогда ClickHouse читает меньше лишнего. Это **не** уникальный ключ.

> [!tip]
> Деньги — `Decimal`, не `Float`. Иначе на [[З11_сверка_sql_bi|З11]] эталон и виджет разъедутся на копейки.

### 2. Порядок хранения

В `ORDER BY` поставьте поля, которыми реально режете запросы (дата продажи, магазин — как в вопросах из паспорта).

Коротко (3–5 предложений) запишите в `notes/` или README: почему именно такой порядок. Логика важнее «ускорения в 100 раз» на учебном sample.

### 3. Загрузка

Залейте данные любым удобным способом: клиент ClickHouse, HTTP, небольшой Python-скрипт. Главное — команда воспроизводится из README или `etl/`.

### 4. Сверка с DuckDB

На одних и тех же условиях сравните хотя бы:

| Что сравнить | Зачем |
|--------------|--------|
| `count(*)` по fact | не потеряли и не удвоили строки |
| `sum` главной метрики | то же число, что даёт эталонный SQL |

Эталон здесь — SQL главной метрики из `sql/canonical_metric.sql`. Расхождение чините сейчас.

### 5. Повторная загрузка

Сделайте load второй раз. Fact не должен раздуться. Либо полный refresh (очистили → залили), либо в README одна фраза: как не поймать дубли.

## Что сдать

- `sql/ddl_clickhouse.sql` (MergeTree и осмысленный `ORDER BY`)
- способ загрузки (скрипт или команды)
- сверка DuckDB ↔ ClickHouse (count и sum главной метрики)
- короткое обоснование порядка в `ORDER BY`

## Проверка

- [ ] В ClickHouse есть ваши таблицы с данными
- [ ] Деньги не во `Float`
- [ ] Суммы сходятся с DuckDB (или расхождение объяснено)
- [ ] Повторный load не плодит дубли (или это явно описано)
- [ ] В тексте нет утверждения, что `ORDER BY` — уникальный ключ как в Postgres
